# 2026-08-15 工作日志

## 产品方案 v1.0 评审 (product-plan-v1/product-plan-v1.html)

评审了用户的产品方案 v1.0。该方案为四层架构（数据接入/知识库引擎/预测链/工程治理横切），含十大功能模块与三阶段路线图。

### 已吸收上一轮建议的点
- 成功指标新增 回测ROI≥3% / 最大回撤≤15%
- 动态置信度衰减 半衰期180天
- 三路融合（规则推理/统计模型/异常检测）+ 三种融合策略
- 三级数据信任分级 trusted/provisional/untrusted

### 上一轮4个盲区在本方案的现状
1. 知识获取瓶颈 — 仍未解决。ML仅作融合辅助信号，未定位为"规则挖掘机"把候选规则灌入沙箱
2. edge vs 命中率 — 部分解决（加了ROI），但置信度字段仍是"创建者给出"，冲突仲裁用 priority×confidence，语义仍偏命中率
3. 特征差异计算层 — 仍未独立成层。差异特征(价差/delta/凯利/成交量)仅作为DSL数据字段散落，无专属计算引擎
4. 规则半衰期闭环 — 部分解决(有衰减)，但无"持续回测→edge跌破阈值自动降权/进沙箱复核"的闭环

### 本文档新问题
- 命中率≥55% 准入门槛不分市场类型(让球vs胜平负基础率不同)，应改为edge相对
- 融合三路输出异构(结构化预测/概率/风险预警)，未定义如何归一化为可比形式(对应G10)
- 统计模型(泊松/ELO)基于球队实力，与"赔率差异"主信号不同源，融合需考虑信号相关性
- 数据接入层假设"机构公开赔率"为trusted，但亚洲盘(澳门/皇冠)真实API有ToS/许可风险，是make-or-break依赖
- 单次检索≤500ms 对规则引擎过于宽松(500条规则求值应是ms级)，性能模型未落地(G6)
- Phase1称"13个算子"但文档只列8个
- 异常检测引擎权重最低，与本产品"数据敏感度"主轴不一致
