## 产品方案 v1.0 评审 (product-plan-v1/product-plan-v1.html)

评审了用户的产品方案 v1.0。该方案为四层架构（数据接入/知识库引擎/预测链/工程治理横切），含十大功能模块与三阶段路线图。

### 已吸收上一轮建议的点
- 成功指标新增 回测ROI≥3% / 最大回撤≤15%
- 动态置信度衰减 半衰期180天
- 三路融合（规则推理/统计模型/异常检测）+ 三种融合策略
- 三级数据信任分级 trusted/provisional/untrusted

### 上一轮4个盲区在本方案的现状
1. 知识获取瓶颈 — 仍未解决。ML仅作融合辅助信号，未定位为"规则挖掘机"把候选规则灌入沙箱
2. edge vs 命中率 — 部分解决（加了ROI），但置信度字段仍是"创建者给出"，冲突仲裁用 priority×confidence，语义仍偏命中率
3. 特征差异计算层 — 仍未独立成层。差异特征(价差/delta/凯利/成交量)仅作为DSL数据字段散落，无专属计算引擎
4. 规则半衰期闭环 — 部分解决(有衰减)，但无"持续回测→edge跌破阈值自动降权/进沙箱复核"的闭环

### 本文档新问题
- 命中率≥55% 准入门槛不分市场类型(让球vs胜平负基础率不同)，应改为edge相对
- 融合三路输出异构(结构化预测/概率/风险预警)，未定义如何归一化为可比形式(对应G10)
- 统计模型(泊松/ELO)基于球队实力，与"赔率差异"主信号不同源，融合需考虑信号相关性
- 数据接入层假设"机构公开赔率"为trusted，但亚洲盘(澳门/皇冠)真实API有ToS/许可风险，是make-or-break依赖
- 单次检索≤500ms 对规则引擎过于宽松(500条规则求值应是ms级)，性能模型未落地(G6)
- Phase1称"13个算子"但文档只列8个
- 异常检测引擎权重最低，与本产品"数据敏感度"主轴不一致

## 特征差异计算层 设计草案 (打磨第1条, 草案待用户确认)

用户选择"慢慢打磨方案"，按依赖顺序逐条对齐，起点=特征差异计算层。

### 架构改动
- 4层 → 5层，插入"特征差异计算层"在数据接入与知识库引擎之间
- 输出 MatchFeatureSnapshot 为共享契约，规则引擎与ML/统计都消费同一份(解"规则与统计模型看不同东西"问题)
- 特征目录 FeatureDefinition 也版本化不可变(扩展6.2不可变性到特征)

### "差异"四族分类法
1. 横截面差异(单时点×多机构): 盘口深度分歧/水位离散/凯利分歧/机构离群 → institution_diff (R003,R008)
2. 时序差异(单机构×时序): 盘口升降/水位变动/变动速率/方向一致性 → odds_change (R001,R002,R011,R007)
3. 共振差异(多机构×时序, 价值最高): 同向调赔机构数/同向分歧/领先滞后/共振强度 → institution_diff高置信 (R004)
4. 衍生异常(计算指标): 凯利背离/成交量异常/波动率突变/隐含概率偏离 → sensitivity (R005,R009,R012)
- league_feature 非差异, 属静态上下文, 进MatchFeatureSnapshot但不经差异引擎

### FeatureDefinition 契约字段
feature_id / name / family / output_type / unit / definition / inputs / time_semantics(point_in_time) / version / emits / trust_basis

### 4条starter示例(映射现有规则)
inst.handicap_dispersion(横截面→R003), temp.handicap_movement(时序→R001/002/011), resonance.sync_count(共振→R004), anom.kelly_divergence(衍生→R009)

### 关键约束
- point-in-time可重算: 特征=raw快照的纯函数, 回测无泄漏
- FeatureDefinition版本化不可变: 改定义=新版本, 历史回测用当时版本
- MatchFeatureSnapshot不可变+携带observed_at/received_at/match_time
- 时间泄漏五步校验作用于特征层(只能用observed_at≤analysis_time的raw)
- 信任继承: feature.trust = min(inputs.trust)
