# 数据来源分层原则（中国体彩锚定 + 本地人工盘赔）

> 权威说明。本文件阐述 football-knowledge-model 的数据来源分层契约，与代码注释互为补充；实现状态以 `../current-status.md` 为准，相关取舍见 `../decisions.md`。

## 1. 一句话原则

**中国体彩数据口只用于获取"基础锚定数据"（且仅限当天在售、当天截止的比赛），详细盘赔由人工操作后生成在本地目录；系统先以体彩基础数据锚定比赛，再据锚定键去对应目录加载人工盘赔明细。历史比赛为纯本地明细，不做体彩锚定。**

体彩不是盘赔的提供方，而是比赛的"定位锚（anchor）"。

## 2. 三层数据流

```
┌─────────────────────────┐   ① 基础锚定（trusted）
│  中国体彩官方数据口       │  —— 联赛 / 主客队 / 开赛时间 / 期号 / 业务日
│  （赛程 + 元信息）        │     不提供详细盘赔
└────────────┬────────────┘
             │ ② 锚定键 = [联赛 | 主队 | 客队]（语义归一后）
             ▼
┌─────────────────────────┐   ③ 详细盘赔明细（provisional，人类生成）
│  本地人工盘赔目录          │  —— 盘口数据.md：让球盘 / 胜平负 / 总进球
│  OE_MANUAL_ODDS_ROOT      │     澳门让球·胜平负详细变化 / 必发交易盈亏
│  <子目录>/盘口数据.md      │
└────────────┬────────────┘
             │ ④ 双源合并（语义键对齐）
             ▼
       merged pool（src_merged_pool）
   aligned（已锚定） / manual_only（未锚定降级）
```

加载顺序不可颠倒：**先锚后明细**。没有体彩锚点，人工盘赔仍可展示，但标记为"未锚定（manual_only）"，绝不伪装成官方在售。

### 锚定窗口（体彩在售截止时间）

体彩锚定**仅取"销售截止日 = 当天"的比赛**，即当天在售且当天截止的场：

- 周一 ~ 周五：当晚 **22:00** 停止售卖（销售截止）
- 周六 ~ 周日：当晚 **23:00** 停止售卖（销售截止）

凡销售截止日非当天的比赛（含跨多日预售的周末场、以及全部已结束的历史场），**不纳入体彩锚定**，一律作为本地盘赔明细（`provisional`）直接消费。历史比赛因此恒定 `manual_only`，前端「历史赛事」页不展示「锚定」列。

## 3. 角色与信任分级

| 来源 | 角色 | 提供内容 | 信任级 | 备注 |
|------|------|----------|--------|------|
| 中国体彩官方（赛程/元信息） | **锚 (anchor)** | 基础骨架：联赛、主客队、开赛时间、期号、业务日 | `trusted` | 仅定位比赛，不供盘赔 |
| 本地人工盘赔（盘口数据.md） | **明细 (value)** | 完整盘口快照、澳门变化、必发盈亏 | `provisional` | 人类生成，诚实标记，不冒充官方在售 |
| 合并池 | 对齐层 | 锚定键匹配结果 | 继承两侧 | `aligned` / `manual_only` |

## 4. 对齐语义

合并池元信息口径：

- `aligned`：人工盘赔已成功对齐到体彩锚点的场次数量。
- `manual_only`：未配置体彩端点（或无对应锚点）的场次数量——预期内的降级态，仍展示但标注"未锚定"。
- `conflicts`：被时间防线（observed/received 早于 match_time）剔除的场次。

前端「数据接入」页的**「锚定」列**（仅对当天在售截止场有意义）直接读取合并池每项的 `merged` 标记：

- `已锚定` = 该项 `merged === true`（已对齐**当天**体彩在售截止锚点）
- `未锚定` = `manual_only`（无官方锚点，或销售截止日非当天，仅本地盘赔）
- `—` = 合并池尚未加载（渲染后自校正）

> 注：锚定仅限"当天在售、当天截止"的比赛（周一~周五 22:00 / 周六~周日 23:00 截止）；**历史比赛不做体彩锚定**，故「历史赛事」页不展示该列。

## 5. 与实现的映射（代码路径）

| 概念 | 代码落点 |
|------|----------|
| 体彩锚定（基础数据） | 前端 `prototype-1.0.0/lottery.js` 的 `sportteryToLottery()`：把体彩基础字段映射为内部场次（含 `business_date`/`serial` 用于锚定与归类），**不期待其携带详细盘赔** |
| 人工盘赔明细 | 后端 `server/src/data/manual/oddsParser.js` 解析 `盘口数据.md`；扫描契约见 `server/src/data/manual/index.js`（`OE_MANUAL_ODDS_ROOT` 下 `<子目录>/盘口数据.md`） |
| 先锚后明细 | 前端 `enrichWithOdds()`：按 `[联赛|主|客]` 语义键去合并池（`_cachedMergedMap`）挂载人工盘赔明细 |
| 锚定状态列 | 前端 `prototype-1.0.0/ingest.js` 的 `renderManualSource()`：交叉合并池 `merged` 标记生成「锚定」列 |
| 诚实降级 | 前端 `lottery.js` 的 `fetchRealMatches()`：官方在售为空 → 回退本地合并池，`_manualOnly=true`，首页默认切「全部」展示，横幅标注"本地人工盘赔池（非官方在售）" |
| 信任分级 | `trusted`（体彩锚定） / `provisional`（人工盘赔）见各数据源 `trust_level` 字段 |

语义键归一函数：`lottery.js` 的 `normLeague()` / `normName()` / `mergedKeyOf()` / `lotteryMergedKey()`（折叠全角/不换行空格/多余空白，并收敛联赛别名，使双源能对齐）。

## 6. 诚实降级与边界

- **零假数据**：未配置体彩端点时，人工盘赔按真实开赛时间归类（多为历史 → 往期），不伪造"今日可买"/在售状态。
- **不越权**：体彩数据口只取基础锚定，详细盘赔一律来自人工目录；系统不假设体彩会提供盘赔明细。
- **可审计**：锚定键、对齐结果、时间防线剔除均落在合并池元信息与推理链中，供复盘与回测追溯。

## 7. 生产态预期

生产应配置体彩锚定端点（`ODDS_SPORTTERY_SCHEDULE_BASE` 等）。届时：

1. 体彩返回**当天在售截止**的锚定场次（trusted 基础数据；周一~周五 22:00 / 周六~周日 23:00 截止）；
2. 系统按锚定键匹配本地人工盘赔目录；
3. 对齐成功的场次既带锚定序号又带盘赔明细（前端「锚定」列显示"已锚定"）；
4. 未配体彩端点时全部为 `manual_only`（预期降级），前端「锚定」列显示"未锚定"。
