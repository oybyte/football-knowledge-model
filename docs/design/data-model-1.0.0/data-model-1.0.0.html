1. 设计原则与约束

不可变性

规则版本（qd_rule_versions）与证据快照（qd_evidence_snapshots）写入后只读。DB 层通过触发器强制禁止 UPDATE / DELETE，所有"修改"为 INSERT 新记录。

时间完整性

所有数据实体强制三时间戳：observed_at（观察时间）/ received_at（接收时间）/ match_time（开赛时间），缺一拒绝入库。

信任分级

数据源、规则、证据均带 trust_level（trusted / provisional / untrusted）。仅 statistics_eligible 的证据纳入正式评估。

可追溯性

预测通过 audit_trail_id 关联审计日志，可回溯完整推理链（规则版本 → 证据 → 数据快照）。

命名规范

  • 表前缀 qd_（knowledge base 领域）。
  • 主键统一 xxx_id，文本 UUID 或业务 ID。
  • 时间字段统一 timestamptz（带时区）。
  • JSON 字段统一 jsonb（支持索引与查询）。
  • 状态字段统一 text + CHECK 约束（不建枚举，便于演进）。

2. 实体关系总览

qd_data_sources (数据源注册表)
    │ 1:N
    ▼
qd_matches (比赛) ──1:N── qd_odds_snapshots (盘口快照)
    │ 1:N
    ▼
qd_match_features (特征)
    │
    ├── 1:N ── qd_evidence_snapshots (证据快照) ──N:1── qd_rule_versions (规则版本)
    │
    ├── 1:1 ── qd_predictions (预测) ──N:1── qd_analysis_commands (分析命令)
    │
    └── 1:N ── qd_backtest_jobs (回测作业)

qd_rule_versions ──1:N── qd_evidence_snapshots
qd_rule_versions ──1:N── qd_backtest_jobs
qd_rule_versions ──1:N── qd_ai_candidates (AI 候选，转正后关联)
qd_audit_log (审计日志，全局不可变)
qd_field_registry (字段注册表，元数据)
关系说明

核心链路：qd_matches → qd_match_features → DSL 求值 → qd_evidence_snapshots（触发时锁定）→ qd_predictions（融合输出）→ qd_audit_log（追溯）。规则与证据为 append-only，比赛与特征为可更新（结果回填）。

5. Append-only 约束实现

规则版本、证据快照、审计日志三张表在 DB 层强制 append-only。通过触发器禁止 UPDATE 与 DELETE，这是工程治理底线——存储层强制不可变，而非依赖应用层逻辑。

-- 通用禁止 UPDATE 触发器函数
CREATE OR REPLACE FUNCTION prevent_update() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION 'append-only: UPDATE is not allowed on %', TG_TABLE_NAME;
END;
$$ LANGUAGE plpgsql;

-- 通用禁止 DELETE 触发器函数
CREATE OR REPLACE FUNCTION prevent_delete() RETURNS trigger AS $$
BEGIN
  RAISE EXCEPTION 'append-only: DELETE is not allowed on %', TG_TABLE_NAME;
END;
$$ LANGUAGE plpgsql;

-- 应用到规则版本表
CREATE TRIGGER trg_rule_versions_no_update
  BEFORE UPDATE ON qd_rule_versions
  FOR EACH ROW EXECUTE FUNCTION prevent_update();

CREATE TRIGGER trg_rule_versions_no_delete
  BEFORE DELETE ON qd_rule_versions
  FOR EACH ROW EXECUTE FUNCTION prevent_delete();

-- 同样应用到 qd_evidence_snapshots 与 qd_audit_log
状态转换的正确实现

规则状态转换（如 draft → proposed）不是 UPDATE 原记录，而是 INSERT 新版本记录（version+1），旧版本标记 superseded。状态机在应用层通过 transitionStatus 接口 + 并发锁实现，DB 层只保证不可变。

扩展字段

dsl-syntax-1.0.0 定义的 10 个扩展字段（如 handicap.initial、water.upper.initial、european.home、over_under.line、bf.volume 等）按相同结构追加到注册表。完整字段全集以 dsl-syntax-1.0.0 第 4 节为准，本 Schema 为机器可读版本。

8. DDL 脚本

完整 DDL 脚本存放于 server/migrations/，按版本号递增。核心表建表脚本示例如下（完整脚本含全部 12 张表 + 触发器 + 索引）。

-- 001_init.sql（节选）
CREATE TABLE qd_rule_versions (
  version_id          text PRIMARY KEY,
  rule_id             text NOT NULL,
  version             int  NOT NULL,
  category            text NOT NULL CHECK (category IN ('odds_change', 'institution_diff', 'sensitivity', 'league_feature')),
  league_scope        jsonb NOT NULL DEFAULT '[]',
  team_scope          jsonb NOT NULL DEFAULT '[]',
  condition           jsonb NOT NULL,
  conclusion          text NOT NULL,
  direction           text NOT NULL,
  base_confidence     numeric(4,3) NOT NULL CHECK (base_confidence BETWEEN 0 AND 1),
  priority            int  NOT NULL CHECK (priority BETWEEN 1 AND 100),
  trust_level         text NOT NULL CHECK (trust_level IN ('trusted', 'provisional', 'untrusted')),
  valid_from          timestamptz NOT NULL,
  valid_to            timestamptz,
  evidence_refs       jsonb NOT NULL DEFAULT '[]',
  evidence_count      int  NOT NULL DEFAULT 0,
  status              text NOT NULL CHECK (status IN ('draft', 'proposed', 'experiment', 'validated', 'approved', 'active', 'superseded', 'deprecated')),
  previous_version_id text,
  created_at          timestamptz NOT NULL DEFAULT now(),
  created_by          text NOT NULL,
  approved_at         timestamptz,
  approved_by         text,
  approval_note       text,
  superseded_at       timestamptz,
  deprecated_at       timestamptz,
  UNIQUE (rule_id, version)
);

CREATE TABLE qd_evidence_snapshots (
  evidence_id          text PRIMARY KEY,
  rule_version_id      text NOT NULL REFERENCES qd_rule_versions(version_id),
  match_id             text NOT NULL REFERENCES qd_matches(match_id),
  observed_at          timestamptz NOT NULL,
  received_at          timestamptz NOT NULL,
  match_time           timestamptz NOT NULL,
  trigger_data         jsonb NOT NULL,
  trigger_conditions   jsonb NOT NULL,
  actual_result        text,
  prediction_correct   boolean,
  trust_level          text NOT NULL,
  statistics_eligible  boolean NOT NULL DEFAULT false,
  eligible_checks      jsonb NOT NULL,
  immutable            boolean NOT NULL DEFAULT true,
  locked_at            timestamptz NOT NULL DEFAULT now(),
  created_at           timestamptz NOT NULL DEFAULT now(),
  CHECK (received_at >= observed_at)
);
