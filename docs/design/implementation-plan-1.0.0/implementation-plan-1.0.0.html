0. 总体路线与原则

0.1 总体路线

基于"先建地基，规则先行，模型随后接入融合"的方向，实施分四个阶段推进：

阶段名称目标完成标志
阶段 0补齐 P0 设计完成编码前的 4 项关键设计（G9/G12/G1/G6）设计文档齐备，可进入编码
阶段 1建地基数据接入 / 特征工程 / 规则存储 / DSL 引擎 / 回测框架端到端可跑通（数据→特征→规则→回测）
阶段 2规则先行文字规则 → DSL → 回测验证 → 转正上线首批规则进入 active 状态
阶段 3模型接入融合统计模型接入三路融合决策层融合预测可追溯

0.2 实施原则

  • 设计先行：每个阶段开始前完成对应设计文档，设计状态与实现状态分离维护。
  • 增量交付：每个任务有可验证的交付物与验收标准，不出现"半成品"。
  • 不可变性：规则与证据存储 append-only，存储层强制禁止 UPDATE/DELETE。
  • 时间完整性：所有数据强制三时间戳（observed_at / received_at / match_time）。
  • 验证门槛：每个里程碑设置明确验收标准，达标才进入下一阶段。
  • 语义化版本：后续演进使用语义化版本，不创建并列版本目录。
