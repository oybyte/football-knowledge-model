# 已确认决策 1.0.0

- 当前应用版本为 `1.0.0`，现役实现由 `prototype-1.0.0` 前端和 `server/` 后端共同组成。
- 架构设计统一以 1.0.0 作为当前基线，后续使用语义化版本演进。
- 架构文档和原型分离维护，设计状态不等同于实现状态。
- 原型阶段保留 data、features、rules 三层解耦。
- 规则和证据最终需要追加式版本化、时间完整性和可追溯性。
- 真实竞彩赛程/赔率适配器和本地人工盘赔源均保留明确的数据源信任等级；模拟数据仅用于测试或降级验证，不冒充生产数据。
- 数据来源分层原则（2026-09-01 用户明确）：中国体彩数据口**只用于获取基础锚定数据**（联赛/主客队/开赛时间/期号/业务日等赛事骨架），**不提供详细盘赔**；详细盘赔由人工操作后生成于本地对应目录（`盘口数据.md`）。系统加载顺序为"先以体彩基础数据锚定比赛 → 再据锚定键去目录加载人工盘赔明细"。信任模型：体彩锚定=`trusted`，人工盘赔明细=`provisional`。对齐语义：合并池 `aligned`=已锚定匹配、`manual_only`=未配体彩端点时的降级态（未锚定，仍可展示但诚实标注）。**锚定窗口限定为"当天在售且当天截止"的比赛（周一~周五 22:00、周六~周日 23:00 体彩停止售卖）；历史比赛不做体彩锚定，仅为纯本地盘赔明细**，故「历史赛事」页不展示"锚定"列。详见 `architecture/data-source-layering.md`。
- SQLite 是默认持久化存储，Redis 可选，但生产形态 Docker Compose 将其作为缓存、队列、锁和共享限流后端接入。
- 生产部署形态必须通过 HTTPS、鉴权、限流、健康检查和 Redis 接线验收；长期线上观测仍未闭环。
